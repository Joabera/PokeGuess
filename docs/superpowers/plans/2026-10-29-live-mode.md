# PokeGuess Live Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `/Live` page that recognizes Pokémon from a camera feed in the browser (ONNX Runtime Web), with Snap sending the detected crop through the existing upload pipeline tagged `source=live`.

**Architecture:** ConvNeXt runs in the browser (WebGPU fp32, WASM int8 fallback) for live boxes and labels; nothing is sent per frame. Snap crops the most confident box and POSTs it to the existing `/api/guess` with `source=live`, so the server's two-model routing, `Guesses` table and ✓/✗ feedback are reused. The web app serves the two browser models from `/models/`.

**Tech Stack:** ASP.NET Core MVC (.NET 10), EF Core, jQuery + ES modules, ONNX Runtime Web 1.20.1 (jsDelivr), Node 22 `node:test`, PyTorch/ONNX Runtime for export, GitHub Actions, Azure App Service.

**Spec:** `docs/superpowers/specs/2026-10-29-live-mode-design.md`

## Global Constraints

- Upload flow on the Guess page must behave exactly as before; all existing tests stay green.
- ONNX Runtime Web pinned to `https://cdn.jsdelivr.net/npm/onnxruntime-web@1.20.1/dist/ort.all.min.js`, loaded only on `/Live`.
- Model files: `convnext_gen1-3.onnx` (fp32, dynamic batch axis `n`), `convnext_gen1-3_int8.onnx` (QUInt8 dynamic quantization), `resnet18_gen1.onnx`; release `models-v2`.
- Browser cache name `pokeguess-models-v2`; progress label "Downloading model — 113 MB, once per device" (28 MB for CPU fallback).
- Thresholds: search hit ≥ 80%, guide box label ≥ 60%; refinement stops below 80% or when side < 15% of frame min side; up to 3 refinement passes; refinement windows 75% of the box side on a 3×3 grid; grid = 1 center window at 80% of min side + 3×3 at 50%; IoU suppression threshold 0.3; stable = seen in ≥ 2 of last 3 frames; guide box = centered square at 60% of min side, averaged over last 5 frames.
- Preprocessing: crop each square to its inner 87.5% (side × 224/256), draw to 224×224, ImageNet mean `[0.485,0.456,0.406]` / std `[0.229,0.224,0.225]`, CHW float32.
- Box drawing: line width `max(2, W/450)`, font `600 ${max(16, W/40)}px system-ui`, label height = font px + 10.
- Snap: most confident green box; JPEG quality 0.9; `source=live`.
- `Guess.Source`: `nvarchar(10)`, required, default `upload`; values `upload` | `live`; unknown → 400 `{ "error": "Unknown source." }` before inference is called.
- `/models/<file>`: only `.onnx`, from `LiveModels:Path` (default `models` under `AppContext.BaseDirectory`); `Content-Type: application/octet-stream`; `Cache-Control: public, max-age=31536000, immutable`.
- Copy (exact): "Live mode needs a camera. You can still upload a picture" (link to Guess); "GPU (WebGPU)" / "CPU (slower)"; "Hold a Pokémon here"; search-mode note when CPU: "Search needs a GPU-capable browser".
- Phones: `facingMode: "environment"`; Flip camera only when more than one `videoinput`; buttons ≥ 44px.

## Review Focus

1. **`/models/` path traversal** (`/models/..%2Fappsettings.json`, `/models/../PokeGuess.Web.dll`) must 404, never serve files outside the models directory. Test in Task 4.
2. **Portrait phone video** (H > W, e.g. 720×1280): every grid, refinement and guide region must lie inside the frame. Test in Task 5.
3. **Interrupted first download**: a partial model must never be stored in the cache; if a cached model fails to load, delete it and download again. Code requirement + manual check in Task 7.
4. **Stale Snap result**: pressing Resume (or Snap again) while a Snap request is in flight must not show the old answer or attach ✓/✗ to the wrong guess (same request-token guard as `guess.js`). Code requirement + manual check in Task 7.
5. **Low-resolution cameras** (320×240): refinement must stop at the 15% minimum and boxes stay in frame. Test in Task 5.
